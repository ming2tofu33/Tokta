# 2026-10-13 메뉴 컴팩트 레이아웃

- 배경: 계정 6개만 넣어도 메뉴 높이가 약 900pt였다. 실제로는 Claude Team 계정 5개를 포함해 9개 이상이라 520pt 스크롤 안에서 2~3개만 보였다. 막대가 대부분 초록이라 위험한 계정이 덜 눈에 띄었고, 막대 색 기준(50%·20%)이 알림 기준(20%·5%)과 달랐다. 디자인 검토 후 사용자 “컴팩트 레이아웃부터 해줘”.
- 결정과 동작:
  1. **계정당 한 줄**: 이름 · 플랜(서비스가 섞인 그룹이면 서비스 이름) · 구간마다 얇은 막대(최대 3개, 위부터 응답 순서) · 가장 빠듯한 구간의 남은 % · 오른쪽 시간 한 가지 · ▸.
  2. **오른쪽 시간 우선순위** (`RowSummary`): 오래된 값(“2시간 전 값”) → 다 씀(“40분 뒤 다시”) → 소진 예측(“21분 뒤 바닥”, 1시간 안이면 빨강) → 가장 빠듯한 구간 리셋까지.
  3. **▸를 누르면 펼침**: 이메일, 결제 정보, 구간별 큰 막대·추이 선·예측, 한도 리셋 횟수, 서비스·사용량 페이지 링크. 예전 카드 내용 그대로다. 오른쪽 클릭 메뉴에도 “자세히 보기”.
  4. **줄을 누르면 서비스 열기**는 그대로 둔다(사용자 확인을 받은 동작).
  5. **추천**: “지금 쓰기” 배지 대신 줄 전체를 옅은 초록으로 칠한다. 마우스를 올리면 “같은 서비스 계정 중 남은 한도가 가장 많아요”.
  6. **색**: 처음엔 평소 회색, 알림 기준선 아래면 주황, 더 아래면 빨강(`StatusLevel(remaining:settings:)`). 아래 후속에서 4단계로 바꿨다. 메뉴바 아이콘 색과 같은 기준이라 설정 → 알림에서 기준을 바꾸면 같이 바뀐다.
  7. 오류와 로그인 안내는 접힌 상태에서도 줄 아래에 보인다.
  8. 메뉴 너비 340 → 360(후속에서 380). 스크롤은 계정 12개를 넘을 때부터(높이 560).
- 결과: 계정 9개가 약 470pt에 스크롤 없이 들어간다. 코드 `Tokta/Core/RowSummary.swift`, `UI/AccountRow.swift`, `UI/MenuContentView.swift`. 테스트 통과(91개), 렌더링 확인(라이트·다크, 펼친 줄). **사용자 앱 사용 확인 전.**

## 후속 — 맨 위 “지금 쓸 계정” 칩 제거 (같은 날)

- 처음엔 메뉴 맨 위에 “지금 쓸 계정” 제목과 서비스별 추천 칩을 두었다.
- 사용자 “뭔가 애매한 언어인 거 같아서 빼는 게 낫지 않을까?” — 무엇을 기준으로 골랐는지 말해주지 않고, 줄 배경색과 같은 정보를 한 번 더 보여줬다.
- 결정: 제목은 다시 “Tokta”, 칩은 뺀다. 줄 배경색은 남기고 기준을 그대로 말하는 설명(“남은 한도가 가장 많아요”)을 붙인다. 고르는 기준 자체는 바꾸지 않았다.

## 후속 — 막대 너비와 4단계 색 (같은 날)

- 사용자 “리셋 시간이 뜨면 바가 완전히 줄어드는데” — 이름(104)·%(40)·리셋 시간(80)·▸가 고정 너비라 막대가 남는 58pt만 받았다.
- 결정: 메뉴 너비 360 → 380, 이름 칸 88, % 칸 36, 시간 칸 72, 간격 6. 막대가 약 114pt로 두 배가 됐다.
- 사용자 “색상으로 얼마나 남았는지 구분이 되는 게 낫지 않을까?” — 평소 회색으로 바꿨던 것을 되돌려 4단계로 나눈다(`BarTone`).
  - 50% 넘음: 초록 · 알림 기준선(기본 20%)까지: 노랑 · 그 아래: 주황 · 위험 기준선(기본 5%) 아래: 빨강.
  - 아래 두 단계는 알림·메뉴바 아이콘과 같은 기준이라 설정에서 바꾸면 같이 바뀐다. 50%는 고정.
  - % 글자는 주황·빨강일 때만 색을 입힌다. 노랑 글자는 밝은 배경에서 잘 안 읽혀서.
- 결과: 테스트 통과(92개), 렌더링 확인(라이트·다크). 앱 사용 확인 전.

## 후속 — 리셋 시간이 없는 줄도 막대 길이 맞춤 (같은 날)

- 사용자 “100프로일 때 리셋 내용이 없을 때랑 리셋 시간 내용이 뜰 때 바 길이가 완전 달라서 보기 좀 불편한 거 같아” — 오른쪽 시간이 없으면 그 칸이 사라져 막대가 시간 칸만큼 길어졌다.
- 결정:
  1. 오른쪽 시간 칸은 비어 있어도 너비를 차지한다. 모든 줄의 막대 길이가 같다.
  2. 한 번도 안 써서 리셋 시각이 없는 구간(Claude 5시간 구간 등)은 “사용 전”으로 표시한다(`RowSummary.Trailing.notStarted`).
  3. 이름이 길면 플랜을 “…”로 자르지 않고 뺀다. 플랜은 펼친 화면 첫 줄(“Max · 이메일”)에 보인다.
- 결과: 테스트 통과(93개), 렌더링 확인. 앱 사용 확인 전.

## 후속 — 줄에서 리셋 시간 빼기 (같은 날)

- 사용자 “리셋 여부를 그렇게까지 보여줄 필요가 없을 거 같아”.
- 결정:
  1. 접힌 줄에는 리셋 시간을 넣지 않는다. 리셋 시간은 ▸로 펼치면 구간마다 보인다. 바로 위에서 넣은 “사용 전” 표시도 뺐다.
  2. 지금 쓰는 데 걸리는 일 세 가지만 % 옆 작은 아이콘으로 남긴다(`RowSummary.Notice`). 문구는 마우스를 올리면 보인다.
     - 모래시계: 다 씀(“40분 뒤 다시 쓸 수 있어요”) · 추세 화살표(주황, 1시간 안이면 빨강): 소진 예측 · 시계: 오래된 값.
  3. 아이콘 칸(14pt)은 비어 있어도 자리를 차지해서 막대 길이가 줄마다 같다. 이름 칸 88 → 100. 막대는 약 160pt.
- 결과: 테스트 통과(92개), 렌더링 확인. 앱 사용 확인 전.

## 후속 — 색을 인디고 + 경고 색으로 (같은 날)

- 사용자 “좀 세련된 색깔로 표현할 수 없을까? 녹색 노랑 빨강 말고?” → 세 후보(차분한 신호등 / 한 색 + 경고만 색 / 쿨→웜) 비교 후 “B로 해줘”.
- 결정 (`Tokta/UI/Palette.swift`, 라이트·다크 따로):
  - 50% 넘음: 인디고(라이트 #6366F1 · 다크 #8B8FF8) · 알림 기준선까지: 연한 인디고(#A5A8F5 · #5559B0)
  - 알림 기준선 아래: 코랄(#F0803C · #F59152) · 위험 기준선 아래: 로즈(#E5484D · #F2555A)
  - 같은 색을 막대, % 글자, 소진 예측 표시, **메뉴바 아이콘 경고 색**이 같이 쓴다(시스템 주황·빨강 대신).
  - 추천 계정 줄 배경도 초록 대신 옅은 인디고.
  - 오류·로그인 안내의 주황은 사용량 단계가 아니라서 시스템 주황 그대로.
- 결과: 전체 테스트 통과(84개), 렌더링 확인(라이트·다크). 앱 사용 확인 전.

## 후속 — 줄을 누르면 펼치기, 색 조합 고르기 (같은 날)

- 사용자 “화살표를 눌러야지만 밑에 내용이 내려오는데 기본으로 눌렀을 때 … 보이면 좋겠어. 그리고 색은 유저가 선택할 수 있으면 좋겠다.”
- 결정:
  1. **줄 어디를 눌러도 펼치고 접는다.** 처음 결정 4번(“줄을 누르면 서비스 열기”, 사용자 확인 동작)을 이번 요청으로 바꿨다. 서비스 열기는 펼친 화면의 “… 열기 · 사용량 페이지” 링크와 오른쪽 클릭 메뉴에서. ▸는 버튼이 아니라 펼침 상태 표시.
  2. **설정 → 일반 → 사용량 색**에서 네 가지 중 고른다(`UsagePalette`, `UserDefaults` `usagePalette`, 기본 인디고): 인디고 · 차분한 신호등 · 쿨에서 웜으로 · 그래파이트. 막대, % 글자, 소진 예측 표시, 추천 줄 배경, 메뉴바 아이콘 경고 색이 같이 바뀐다. 단계 기준선은 그대로.
- 개발 중 잡은 버그: `UsagePalette.nsColor(for: StatusLevel)` 안의 `.critical`이 `BarTone`이 아니라 `StatusLevel`로 해석돼 자기 자신을 끝없이 불렀다. 위험 단계(5% 이하) 계정이 있으면 앱이 멈췄을 것. 설치 전 렌더링에서 발견, `BarTone.critical`로 명시하고 테스트 추가.
- 결과: 전체 테스트 통과(85개), 렌더링 확인(색 조합 4개 × 라이트·다크). 앱 사용 확인 전.

## 후속 — 펼친 화면 정리 (같은 날)

- 펼치면 접힌 줄의 얇은 막대 아래에 구간마다 큰 막대가 또 나와 같은 정보를 두 번 보여줬다. 디자인 검토 후 사용자 “펼친 화면 정리해보자”.
- 결정:
  1. 큰 막대를 뺀다. 구간마다 글자 한 줄: **구간 이름 · 남은 % · 리셋까지 · 추이 선**. 열을 맞춰(`Grid`) 구간끼리 비교하기 쉽게.
  2. % 글자는 접힌 줄과 같은 기준으로 알림 기준선 아래일 때만 경고 색.
  3. 소진 예측은 그 구간 바로 아래 한 줄(“이 속도면 21분 뒤 바닥”).
  4. 맨 위는 “플랜 · 이메일”과 결제 정보, 맨 아래는 오래된 값 안내, 한도 리셋 횟수, 서비스·사용량 페이지 링크. 그대로 유지.
  5. 리셋 시각이 없고 한 번도 안 쓴 구간은 “사용 전”.
- 결과: `UsageBar` 삭제. 전체 테스트 통과(88개), 렌더링 확인(라이트·다크, 예측 있는 줄·한도 리셋 횟수·구간 3개). 앱 사용 확인 전.
