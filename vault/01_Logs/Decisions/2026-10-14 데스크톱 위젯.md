# 2026-10-14 데스크톱 위젯

- 배경: 로드맵 다음 단계 “위젯”. 사용자 “앱 위젯 작업해볼까? 어떤 걸 뭘 어떻게 보여주는 게 좋을까?” → 크기별 시안 → “응 그렇게 진행해줘”.
- 결정:
  1. 세 크기 모두 “지금 어느 계정을 쓰면 되나”에 답한다.
     - **작게**(서비스 하나, 위젯 편집에서 고름, 기본은 메뉴 맨 위 서비스): 지금 쓸 계정 이름, %, 막대, “5개 중 3개 여유”(알림 기준선 위 · 오류·오래된 값 제외).
     - **중간**: 서비스마다 지금 쓸 계정(계정이 하나면 그 계정) 한 줄. 최대 4개.
     - **크게**: 메뉴와 같은 묶음별 전체 계정. 추천 줄은 옅게 칠한다. 12줄(묶음 제목 포함)을 넘으면 “계정 N개 더”.
  2. **누르면 그 계정으로 연다** — `tokta://open/<계정 ID>` → 앱이 [[2026-10-13 계정 바로 쓰기]]로 연다(Claude·Cursor 창, CLI 터미널). 작은 위젯은 지금 쓸 계정.
  3. 추천·색 단계·오류 판단은 앱에서 끝내고 위젯은 그리기만 한다. 색은 설정의 사용량 색을 따른다.
  4. **떠 있는 HUD 창 결정은 위젯으로 대신**한다(바탕화면 위젯이 그 역할).
- 데이터 흐름: 위젯은 사용량을 직접 읽지 않는다. 앱이 읽을 때마다(`UsageStore.onChange`) App Group 공유 폴더에 `widget.json`을 쓰고(`WidgetSync`), 보이는 내용이 바뀌었을 때만 `WidgetCenter.reloadAllTimelines()`. 위젯은 15분마다도 다시 그려 “몇 분 전”·오래된 값(15분)을 맞춘다. 앱이 꺼져 있으면 마지막 값이 흐리게 남는다.
- 구조: `ToktaWidget/`(위젯 확장, 샌드박스), `Shared/`(앱·위젯 공용: `WidgetData`, `UsagePalette`, `StatusLevel`·`BarTone`), `Config/`(entitlements, Info.plist — 앱의 `tokta` URL 스킴, 위젯 확장 지점). App Group `<팀 ID>.app.tokta.shared`(지금은 `Config/Tokta.xcconfig`).
- 결과: 전체 테스트 통과(101개). Release 빌드 팀 서명 통과, 위젯에 App Group 포함 확인. 위젯 화면 렌더링 확인(세 크기 × 라이트·다크, 예시 데이터 — 내 Mac의 App Group 폴더는 셸에서 읽을 수 없어 실제 데이터는 확인 전). **위젯 갤러리에 뜨는지·누르면 열리는지 사용자 확인 전.**
