# 2026-10-15 iPhone 앱

- 배경: 사용자 “tokta 데스크탑에서 보이는 내용을 폰으로도 확인할 수가 있나?”, “맥이 꺼져 있다면 핸드폰으로는 볼 수가 없는 건가?” → [[iPhone 앱 조사 2026-10]] → 1단계 진행. 사용자 승인: Apple Developer 계정에 iCloud 컨테이너 등록(“응”), 이 맥(과 나중에 iPhone)을 개발용 기기로 등록(“응 그렇게 해줘”).
- 결정:
  1. **맥이 읽고 iPhone은 보여준다.** 맥 설치본이 위젯 데이터(`WidgetData`)를 본인 iCloud의 CloudKit 개인 데이터베이스(`iCloud.app.tokta`, 레코드 `UsageSnapshot/latest`)에 올린다. 보이는 내용이 바뀌었거나 10분이 지났을 때만. 로그인 정보는 올리지 않는다(계정 이름·플랜·남은 %·리셋 시각·추천·표정).
  2. iCloud 권한은 **Release(설치본)에만**(`Config/Tokta-Release.entitlements`). Debug·테스트는 권한이 없고, `CloudSync.isAvailable`이 권한을 확인해 건너뛴다(권한 없이 CloudKit을 부르면 앱이 멈춘다).
  3. **맥이 꺼져 있을 때**: 받은 값에 구간별 리셋 시각이 있어서, 리셋 시각이 지난 구간은 다시 찼다고 추정한다(`WidgetData.estimated(at:)`). “추정” 표시. 서비스 추천도 추정값으로 다시 고른다. 맥 위젯도 앱이 꺼져 있으면 같은 추정을 쓴다.
  4. **iPhone 앱**(`ToktaPhone`, `app.tokta.phone`, iOS 18+): 맨 위 “맥에서 N분 전에 받은 값”(15분 넘으면 주황 + 안내), 지금 쓸 계정(캐릭터·%·리셋까지), 나머지 서비스, 모든 계정. 당겨서 새로고침, 앱을 열 때마다 받기, 맥이 올리면 CloudKit 조용한 알림으로 깨어나 받기. 계정을 누르면 그 서비스 웹을 연다(어느 계정으로 열지는 iPhone에서 고를 수 없다).
  5. **iPhone 위젯**(`ToktaPhoneWidget`): 맥 위젯 코드(`ToktaWidget/`)를 그대로 iOS로도 빌드. App Group `group.app.tokta.shared`.
  6. 공용 코드(`Shared/`)의 색·캐릭터를 맥·iPhone 공용으로(`PlatformColor`). `palette.nsColor(for:)` → `platformColor(for:)`.
- 서명: 이 맥을 개발용 기기로 등록(`-allowProvisioningDeviceRegistration`), 맥 Release에 iCloud가 든 프로비저닝 프로필이 붙었다.
- 결과: 맥 테스트 통과(126개, 추정 테스트 포함). iPhone 앱·위젯 시뮬레이터 빌드 통과. 시뮬레이터에서 예시 데이터(3시간 전 값)로 화면 확인 — 오래된 값 안내, 리셋 지난 구간 “추정”, 추천 다시 고르기. **실제 iCloud 왕복(맥이 올리고 iPhone이 받기)·실제 iPhone 설치·위젯·조용한 알림은 확인 전**(시뮬레이터에 Apple ID 로그인 없음).
- 남은 것: 맥 설치본 실행 후 iCloud 올리기 로그 확인 → iPhone을 맥에 연결해 Xcode로 설치(그때 iPhone 기기 등록) → 받기 확인. iPhone 리셋 알림은 아직 없음.

## 후속 — 실제 iPhone 설치 (같은 날)

- 맥 설치본(빌드 24)이 iCloud에 올리는 것 확인(`log` — `iCloud에 올림`). zsh에서는 `log`가 내장 명령이라 `/usr/bin/log show --info --predicate 'subsystem == "app.tokta.Tokta"'`로 본다.
- 사용자 iPhone을 개발용 기기로 등록하고 커맨드라인으로 설치(`xcodebuild -target ToktaPhone -sdk iphoneos -allowProvisioningUpdates -allowProvisioningDeviceRegistration`, `xcrun devicectl device install app`).
- 처음 실행에서 오류 문구, 다시 실행하니 정상 — 막 등록한 iCloud 컨테이너가 준비되기 전이었던 것으로 보인다(확실하지 않음). **사용자 확인: 앱에 숫자가 보이고 iPhone 위젯도 잘 보임.**
- 앱 아이콘: 맥 아이콘 원본(`design/menu-bar-v1/ToktaGlassMaster.png`)은 둥근 모서리 밖이 흰색이라, 가운데를 잘라 꽉 찬 정사각형 1024px로(`ToktaPhone/Assets.xcassets/AppIcon`). iOS가 모서리를 둥글게 자른다.

## 후속 — iPhone 리셋 알림 (같은 날)

- 사용자 “폰에서 리셋 알림 받게 해줘”.
- 결정: 맥과 같은 기준 — **알림 기준선 아래로 내려간 구간만, 그 구간의 리셋 시각에**(`WidgetData.resetAlerts(after:)`). 오류가 붙은 계정·지난 리셋은 뺀다. 문구 “Claude · 메인 / ^o^ 5시간 한도가 다시 채워졌어요”.
- iPhone이 받은 리셋 시각으로 **로컬 알림을 미리 예약**한다(`ResetNotifier`). 앱을 닫아도, 맥이 꺼져 있어도 그 시각에 온다. 새 값을 받을 때마다 다시 맞춘다(없어진 예약 지움, 같은 알림은 같은 id, 가까운 것부터 50개까지).
- 켜고 끄기: iPhone 앱 아래 “한도가 다시 차면 알림”(기본 켬). 맥 설정 → 알림의 리셋 알림을 끄면 iPhone도 보내지 않는다(위젯 데이터에 `resetAlerts`).
- 맥이 켜져 있으면 맥도 같은 리셋 알림을 보내서 두 기기에 하나씩 온다.
- 결과: 테스트 통과(128개, 예약 규칙 2개 추가). 사용자 iPhone에 설치. **실제 알림 수신 확인 전**(리셋 시각이 와야 확인된다).

## 후속 — 알림 정리 (같은 날)

- 사용자 “알람이 복잡한데 어떻게 하는 게 좋을까?” → 받을 곳 **iPhone(추천)**, 종류 **세 가지로 줄이기(추천)**. 위 “iPhone 리셋 알림” 방식(iPhone이 직접 판단·맥과 iPhone에 하나씩)은 이것으로 바뀐다.
- 결정:
  1. **알림은 세 가지.** 곧 바닥나요(기준 아래로 내려가거나 이 속도면 1시간 안에 바닥날 때, 한 주기에 한 번 — 기준선 알림과 소진 예측을 하나로 합침) · 다시 찼어요(곧 바닥나요가 왔던 한도의 리셋 시각) · 내일 결제(결제 전날 오전 9시). 2차(5%) 알림은 없앴고 5%는 메뉴 색(빨강)에만 쓴다.
  2. **맥이 정하고, 받을 곳은 하나.** 맥 설정 → 알림의 “받을 곳”: iPhone(기본) / 이 맥 / 둘 다. iPhone으로 보낼 알림은 위젯 데이터(`alerts`: 예약 알림·최근 2시간 알림)에 실어 iCloud로 넘기고, iPhone Tokta(`PhoneAlerts`)는 판단 없이 보내기만 한다. 예약 알림은 미리 예약해 맥이 꺼져 있어도 오고, 곧 바닥나요는 맥이 정한 지 1시간 안에 iPhone이 받았을 때만 보낸다(같은 알림은 한 번).
  3. **설정은 맥에서만.** iPhone 앱 아래 “알림”은 지금 iPhone으로 오는지만 보여준다.
- 결과: 맥 테스트 통과(받을 곳·합치기·넘기기 테스트 추가). iPhone 빌드·설치, 맥 설치본 다시 설치. **실제 iPhone 알림 수신은 확인 전** — 곧 바닥나요는 맥이 올린 뒤 iPhone이 깨어나 받아야 와서 몇 분 늦을 수 있다.

## 후속 — iPhone 화면 다시 그리기 (2026-10-16)

- 사용자 “폰 앱은 어떻게 디자인 하면 좋을지 웹시안으로 만들어서 상의해보자” → `design/phone-v1`(공개 전 정리로 지움)(A 맥 메뉴 그대로 · B 서비스 타일 · C 다시 차는 순서 + 공통 이번 달 탭·잠금 화면 위젯) → 사용자 “B 타일에 C 다시 차는 것 붙여서 진행해줘”.
- 결정(지금 화면): 맨 위 “맥에서 N분 전에 받은 값” 알약(오래되면 주황 + 추정 안내) → 지금 쓸 계정 넓은 카드(캐릭터) → **서비스 타일 2열**(가장 여유 있는 계정 %, 계정마다 아래부터 차는 작은 칸, 추정이면 흐리게 + “추정”) → **다음에 다시 차는 것 3개**(리셋 시각 순, 95% 넘게 남은 구간·오류 계정 제외) → 알림 받는 곳 한 줄. 타일을 누르면 그 서비스 계정 목록.
- 이번 달 탭·잠금 화면 위젯은 아직(이번 달은 맥이 계산해 iCloud로 같이 보내야 한다).
- 결과: iPhone 빌드, 시뮬레이터(예전 예시 데이터)로 화면 확인, 사용자 iPhone에 설치. 실제 값으로는 확인 전.

## 후속 — 타일 게이지 (2026-10-17)

- 사용자 “게이지바를 세로로 줄어들게 보이니까 차이가 거의 보이지 않아” → 비교 시안 `design/phone-tile-v1`(공개 전 정리로 지움)(A 가로 막대+숫자 · B 링 · C 긴 세로 칸) → A(추천). 사용자: “5계정을 한꺼번에 잘 보고 싶은 사람들을 타겟팅”.
- 결정: 타일 안 계정은 **이름 · 가로 막대 · %** 한 줄씩. **계정 3개 이상인 서비스는 한 줄을 다 쓰는 넓은 타일**로 모든 계정을 줄이지 않고 보여주고, 계정마다 구간별 막대(5시간·주간)를 겹친다. 넓은 타일은 큰 숫자 대신 “→ 디자인이 가장 여유”. 나머지 서비스는 두 개씩.
- 조사 도우미 `Josa`를 `Shared/`로 옮겨 iPhone에서도 쓴다.
- 결과: 시뮬레이터에서 Claude 5계정 예시로 확인, 사용자 iPhone에 설치.

## 후속 — iPhone 색 조합 (2026-10-17)

- 결과: 사용자 iPhone에 설치, 화면 확인(맥과 같게).
