# 톡타 핵심 기능과 화면 재기획

사용자가 동의한 방향: **AI를 여러 개 구독하는 사람이 지금 쓸 계정, 다음 리셋, 다음 결제를 한눈에 판단한다.**

이 문서는 그 방향의 구체 설계안이다. 현재 작업 폴더의 코드와 결정 기록을 확인해 작성했으며, 앱 변경·실기기 검증을 완료했다는 뜻은 아니다. 세부 수치와 출시 순서는 초기 검증을 위한 제안이다.

> **사용자 결정 (2026-10-17):** 기획서대로 1차부터 진행. 단, ① 신규 사용자 알림 기본은 **Mac**(기획서대로, 10/15의 iPhone 기본을 바꿈 — 기존 사용자 설정은 유지), ② **메뉴의 계정 목록은 지금처럼 모두 펼쳐 둔다**(아래 B의 “접힌 요약”은 쓰지 않음 — 10/16 “이전처럼 남은 사용량을 한 눈에”). 시작 전 지금까지의 작업을 커밋(`3504e0f`).

## 1. 누구에게 어떤 가치를 주는가

- 핵심 사용자: Claude·Codex·Cursor를 업무에 자주 쓰며, 여러 구독이나 계정을 관리하는 개인.
- 초기 집중 사례: Claude 계정 5개를 한 번에 비교해야 하는 사용자.
- 단일 계정 사용자도 잔여 한도·리셋·알림만으로 바로 도움을 받아야 한다.
- 매일의 가치: 한도 확인과 다음 계정 선택에 드는 수고를 줄인다.
- 월간 가치: 결제 전에 사용 기록과 구독 정보를 함께 검토한다.
- 제품의 성공: 자주 앱을 열게 하는 것이 아니라, 계속 켜 두고 필요한 순간에 도움을 받게 하는 것.

### 제공 서비스의 범위

| 서비스 | 처음 연결 화면 | 표시·행동 범위 |
|---|---|---|
| Claude | 우선 노출 | 수집 가능한 세션·주간 한도, 계정별 Tokta 웹 창 열기 |
| Codex | 우선 노출 | ChatGPT 계정의 Codex 한도, 계정별 Codex CLI 실행 |
| Cursor | 우선 노출 | 수집 가능한 사용량, 계정 대시보드 열기. Cursor 편집기 계정 전환으로 표현하지 않음 |
| Grok·Antigravity | ‘다른 서비스’에서 연결 | 기존 지원 유지, 실제 읽는 한도와 실행 대상을 명시 |
| Grok Bot | 연결한 Cursor의 부가 한도 | 별도 결제가 확인되지 않으면 구독 수·금액에 중복 집계하지 않음 |

표시명을 Codex로 바꾸더라도 기존 ChatGPT 계정 저장 식별자는 보존한다. 일반 ChatGPT 채팅 한도나 Gemini 앱 한도를 제공한다고 표현하지 않는다. 신규 서비스 추가는 사용자 요청·조회 신뢰도·후속 행동 가능성을 보고 결정한다.

## 2. 핵심 기능 명세

### F1. 기준 계정과 대안

**기준 계정**은 사용자가 고정한 계정 → 해당 서비스에서 톡타로 마지막으로 연 계정 → 최초 선택한 계정 순으로 정한다. 외부 앱에서 실제 사용 중인지 알 수 없으므로 ‘사용 중’으로 단정하지 않는다. 카드에는 ‘고정한 계정’ 또는 ‘최근 연 계정’이라고 표시한다.

- 1계정일 때도 같은 핵심 카드를 표시한다.
- 평소에는 기준 계정을 유지하고, 숫자가 조금 달라질 때마다 추천을 바꾸지 않는다.
- 기준 계정의 관련 한도 중 하나가 경고선 이하이거나, 유효한 예측상 1시간 이내 소진이면 대안을 제시한다.
- 대안은 기본적으로 **같은 서비스·같은 그룹** 안에서 찾는다. 다른 그룹을 포함하려면 사용자가 명시적으로 범위를 바꾼다. 그룹 없는 계정은 ‘기본’ 그룹으로 취급한다.
- 오류·15분 초과 오래된 값·조회 전·추정값은 확정 추천에서 제외한다. 관련 한도가 누락된 후보도 ‘상태 확인 필요’로 둔다.
- 유효한 후보 중 관련 한도의 최저 잔여율이 높은 계정을 우선한다. 이는 ‘한도 여유’ 비교이며 모델 성능이나 남은 작업량 비교가 아니다.
- 초기 기준: 경고선 20%, 대안과의 차이 10%p 이상일 때 전환을 권한다. 기준 계정이 소진됐다면 여유가 적은 대안도 제시하되 ‘이 계정도 빠듯함’ 표시. 이 수치는 사용자 관찰 후 조정한다.
- 동률이면 최근 연 계정, 그다음 사용자가 정한 순서를 따른다.
- 현재 서비스가 막혔다고 다른 서비스로 자동 변경하지 않는다. 다른 서비스는 보조 목록에서 직접 선택한다.
- 실행 버튼은 대상 계정과 실행 위치를 명시한다. 자동 전환은 하지 않는다. 기존 대화·프로젝트의 자동 이전도 제공하지 않는다.

추천 문구 예: ‘개인은 세션 12% 남음. 업무는 세션 78%·주간 61%로 더 여유 있어요.’ 그룹 간 추천을 허용한 경우의 예시다.

### F2. 리셋과 다시 쓸 수 있는 시점

- 세션·주간 한도를 각각 이름, 잔여율, 리셋 시각과 함께 표시한다.
- 리셋은 ‘한 구간이 회복되는 사건’이며 계정 전체가 100%가 되는 뜻이 아니다.
- ‘다음 리셋’은 가장 가까운 구간 리셋을 보여준다. 다른 구간이 소진된 경우 ‘주간 한도 때문에 계속 제한될 수 있어요’를 붙인다.
- 여러 구간이 소진돼 있다면 알려진 모든 차단 구간이 풀릴 예정인 시점을 별도로 표시할 수 있다. 하나라도 리셋 시각을 모르면 ‘다시 사용 가능한 시각 확인 필요’로 둔다.
- Mac 재조회 성공으로 회복을 확인했을 때만 ‘다시 사용 가능’으로 표시한다.
- 시각만 지났다면 ‘리셋 예정 시각이 지났어요 · 최신 상태 확인 필요’. 특히 iPhone·위젯에서 추정 100%를 확정된 잔여량처럼 크게 보여주지 않는다.
- 미래 잔여량은 그 사이의 사용을 모르므로 보장하지 않는다.

### F3. 필요한 순간의 알림

| 종류 | 조건 | 문구·행동 |
|---|---|---|
| 한도 임박 | 경고선 또는 유효한 1시간 내 소진 예측 | ‘개인 세션 12% 남음’ + 가능한 대안 열기 |
| 리셋 | 임박 알림을 받은 구간 또는 사용자가 지정한 구간 | 예약은 ‘리셋 예정 시각이에요’, 재조회 확인은 ‘세션 한도가 회복됐어요’ |
| 결제 | 입력·확인한 다음 결제일 전날 | ‘내일 Cursor 결제 예정’ + 이번 달 보기 |

- 기준선 알림과 예측 알림은 같은 계정·구간·주기에서 중복 발송하지 않는 기존 방향을 유지한다.
- 같은 계정의 여러 구간이 동시에 임박하면 한 알림으로 묶는다. 서로 다른 계정 알림은 임의로 누락하지 않는다.
- 기존 사용자 수신처는 유지한다. 신규 사용자는 Mac을 기본으로 제안하고, iPhone 수신 확인 후 iPhone/둘 다를 선택하도록 한다.
- iPhone 수신은 동기화·백그라운드 실행에 따라 늦을 수 있다. 긴급한 즉시 알림을 보장하지 않는다. Mac에서 테스트 알림 보내기와 iPhone 수신 확인을 제공한다.
- ‘오늘 이 계정 알림 끄기’를 제공하고, 억제된 알림은 예약 알림에도 반영한다.
- 알림 버튼을 누를 때 현재 계정 상태를 다시 점검한다. 삭제된 계정·로그인 만료라면 계정 관리로 안내한다.

### F4. 계정 비교와 기록

- 전체 계정에서 같은 서비스 계정을 같은 열 기준으로 비교한다. 계정 5개를 숨기거나 ‘+2’로 축약하지 않는다.
- 순서는 기본적으로 사용자가 정한 순서를 유지한다. ‘여유 많은 순 / 리셋 빠른 순’은 명시적인 정렬 옵션이다.
- ‘여유’의 퍼센트가 어느 구간 기준인지 표시한다. 합산 잔여율이나 서로 다른 서비스의 통합 퍼센트는 만들지 않는다.
- 상세에는 구간별 잔여량, 리셋, 최신 조회 시각, 최근 7일 관측 추이를 제공한다.
- 현재 ‘오늘 하루’ 타임라인은 계정 상세의 접힌 기록 영역으로 이동한다. 관측 사이의 증가를 정확한 작업 시간으로 표시하지 않는다. 수집 공백은 빈 구간으로 남긴다.
- 소진 예측은 최근 충분한 관측과 증가가 있을 때만 표시한다. 표본·시간 범위 기준은 구현 단계에서 기존 예측기 검토 후 정하고, 모든 화면이 같은 결과를 사용한다.

### F5. 이번 달 구독 점검

- 상단: **등록한 구독의 월 환산액**, 다음 결제, 구독 목록.
- 월 환산액과 이번 달 실제 결제액을 구분한다. 후자는 결제 내역이 없으면 제공하지 않는다.
- 다른 통화는 각각 합계를 표시한다. 환율 기능 없이 한 금액으로 합치지 않는다.
- 금액 미입력·회사 부담·무료 크레딧·연간 결제 상태를 구분한다. 모르는 금액은 0원으로 간주하지 않는다.
- 목록: 서비스/계정, 비용 부담, 월 환산액, 다음 결제일, 마지막 사용 증가 관측일, 관측 상태, ‘구독 관리’.
- 구독 관리 링크가 해당 계정 로그인을 보장하지 않으면 ‘웹에서 구독 관리’라고 표시한다. 앱에서 자동 해지하지 않는다.
- 사용 관측을 충분히 확보한 경우에만 ‘최근 관측에서 사용 증가가 적었어요’라는 점검 카드를 제공한다. 기간이 지났다는 이유만으로 기록이 충분하다고 판정하지 않는다.
- 초기 출시에서는 사용 적음 자동 판단보다 마지막 증가 관측일·수집 기간·공백을 먼저 제공한다. 유휴 판단 기준은 실제 기록을 보며 검증한다.
- ‘구독 가치 18%’, ‘해지하면 아껴요’, ‘모두 잘 쓰고 있어요’ 같은 자동 가치 판단을 제거한다.
- 관측상 한도 소진 횟수는 상세 참고 정보로 둔다. 이것을 실제 업무 중단 횟수나 톡타가 막아준 중단 횟수로 바꾸지 않는다.

## 3. 화면 구조

### A. 처음 실행 — 한 계정의 실제 값까지

1. ‘쓰는 AI를 연결하세요’: Claude / Codex / Cursor, 아래 ‘다른 서비스’.
2. 선택한 서비스의 연결 방법과 실제 제공 범위 → 로그인 → 계정 확인 → 첫 조회 성공.
3. 계정 이름·그룹은 기본값을 제공하고 이후 수정 가능. 이름 입력이 연결의 필수 장애물이 되지 않게 한다.
4. 첫 실제 잔여량을 보여준 뒤 ‘메뉴바에서 바로 볼 수 있어요’. 두 번째 계정은 선택 사항.
5. 알림 권한과 수신처는 ‘나중에’ 가능. iPhone 설치를 시작 조건으로 요구하지 않는다.

계정 행이 생성됐다는 이유만으로 연결 완료로 처리하지 않는다. 로그인 취소·첫 조회 실패에는 ‘다시 시도 / 나중에’를 제공한다. 사용 예시 데이터는 실제 연결 성공으로 계산하지 않는다.

### B. Mac 메뉴바 — 지금 무엇을 할지

> 사용자 결정: 계정 목록은 접지 않고 지금처럼 모두 펼친다. 상태 카드·대안·다음 리셋을 그 위에 더한다.

고정 너비 약 380pt를 유지한다. 상단부터 상태 카드 → 필요한 대안 → 다음 리셋 → 같은 서비스의 계정 요약 → 다른 서비스 접힌 요약 → 전체 계정/이번 달/설정 순서다. 내용이 길면 목록만 스크롤하고 핵심 카드·하단 이동은 유지한다.

```text
Tokta                          새로고침

고정한 계정 · Claude / 개인
세션   12% 남음       15:20 리셋
주간   46% 남음       월 09:00 리셋
2분 전 확인
[개인 계정으로 Claude 열기]

같은 그룹의 ‘보조’가 더 여유 있어요
세션 78% · 주간 61%
[보조 계정으로 Claude 열기]

다음 리셋 · 개인 세션 · 42분 후
주간 한도는 그대로 유지돼요

Claude 계정 5개                 펼치기
다른 서비스                    펼치기
───────────────────────────────────
전체 계정        이번 달        설정
```

예시 숫자·시각은 설명용이다. 평소에는 대안 영역을 숨겨 카드가 짧아진다. 1계정이면 계정 목록 중복을 생략한다. 조회 오류에서는 ‘여유 없음’ 대신 ‘확인 필요’와 재로그인/새로고침 행동을 보여준다.

메뉴바 숫자는 고정/최근 연 기준 계정의 한도 잔여율로 통일한다. 여러 서비스의 최솟값을 하나의 숫자로 섞지 않는다. 값이 없거나 오래됐으면 ‘—’ 또는 확인 필요 표시로 바꾼다. 숫자 숨기기 옵션을 유지한다.

### C. Mac 큰 창 — 전체 계정 / 이번 달

창 상단에 두 탭을 둔다. 기본 진입은 ‘전체 계정’, 결제 알림으로 열면 ‘이번 달’. 설정은 별도 버튼으로 둔다.

**전체 계정**

```text
[전체 계정]  [이번 달]                  + 계정 연결
서비스: Claude ▾    그룹: 개인 ▾    정렬: 내 순서 ▾

계정       세션 잔여        주간 잔여       상태/행동
메인       12% · 42분 후    46% · 월요일    [열기]
보조       78% · 3시간 후   61% · 화요일    [열기]
디자인     34% · 1시간 후   20% · 월요일    [열기]
리서치     —               —              [다시 로그인]
실험       63% · 이전 값    51% · 이전 값   [새로고침]

행 선택 → 상세 패널: 모든 구간 / 조회 시각 / 기록 / 구독
```

좁은 창에서는 열을 잘라내지 않고 계정별 두 줄 카드로 전환한다. 지원하지 않는 구간은 ‘해당 없음’, 조회하지 못한 구간은 ‘확인 필요’로 구분한다. 막대만으로 의미를 전달하지 않고 항상 구간명과 숫자를 붙인다.

**이번 달**

1. 등록한 구독 월 환산액 + 금액 미입력 개수.
2. 가까운 결제 일정 최대 3개 + 전체 보기.
3. 구독별 비용·결제일·관측 기록 목록.
4. 기록이 충분할 때만 점검 제안. 데이터가 없어도 결제·구독 편집은 바로 사용 가능.

### D. iPhone — 멀리서 상태 확인

- 첫 화면 제목 ‘계정 현황’. 맨 위 ‘Mac에서 받은 시각’과 계정별 실제 관측 시각을 구분한다.
- 즐겨찾는 서비스의 넓은 계정 타일을 먼저 배치한다. Claude 5계정은 모두 이름·세션·주간 두 줄로 비교한다.
- 같은 계정이 위 추천 카드와 타일에 반복되지 않게 독립된 큰 추천 카드는 제거한다. 필요한 대안은 해당 타일 안 짧은 안내로 표시한다.
- 다른 서비스는 공간에 따라 2열 타일, 계정이 많으면 넓은 타일을 유지한다. 색 조합의 Mac 따르기/개별 선택도 유지한다.
- 다음 리셋 최대 3개, 각 항목에 구간과 ‘예정’ 여부 표시.
- 계정 상세: 모든 한도, 받은 시각/관측 시각, ‘서비스 웹사이트 열기’. 특정 계정으로 로그인된다고 약속하지 않는다.
- 당겨서 새로고침은 iCloud의 최신 값을 가져오는 동작임을 표시한다. Mac에 즉시 재조회를 명령하는 기능처럼 보이지 않게 한다.
- 마지막 수신만으로 Mac이 꺼졌다고 단정하지 않는다. ‘새 값이 아직 도착하지 않았어요’로 안내한다.
- ‘이번 달’ iPhone 탭은 2차: Mac 월간 데이터 계약과 동기화 구현 뒤 제공한다.

### E. 위젯

| 크기/종류 | 내용 | 누르면 |
|---|---|---|
| 작은 상태 | 지정 계정, 제한 구간 잔여율, 리셋, 관측 시각 | 해당 계정 상세 |
| 중간 비교 | 지정 서비스의 계정 최대 3개와 전체 개수 | 해당 서비스 전체 계정 |
| 큰 비교 | 공간 내 계정 목록, 넘치는 계정 수 | 전체 계정 |
| 다음 리셋 | 계정·구간·예정 시각, 남는 제한 안내 | 해당 계정 상세 |

기존 위젯 종류는 유지하고 데이터·상태 표현을 통일한다. 위젯 누르기는 기본적으로 상세 화면을 열도록 제안하며, 기존 계정 실행 동작을 선호하는 사용자를 위해 선택 옵션으로 보존한다.

## 4. 모든 화면의 공통 상태

| 상태 | 보여줄 것 | 추천·알림 |
|---|---|---|
| 정상 최신 | 실제 잔여량, 구간, 관측 시각 | 추천 가능 |
| 빠듯함 | 막히는 구간 강조 + 유효한 대안 | 주기당 중복 없이 임박 알림 |
| 소진 | 해당 구간과 리셋, 다른 제한 | 대안이 없으면 대기 안내 |
| 갱신 중 | 마지막 값과 원래 관측 시각 | 갱신 시작이 최신화로 간주되지 않음 |
| 오래됨 | 마지막 값 흐리게, N분 전, 재조회 | 확정 추천·임박 판단 제외 |
| 로그인 만료 | ‘다시 로그인’, 이전 값은 보조 | 정상 또는 소진으로 표시하지 않음 |
| 연결/조회 전 | 진행 상태·실패 이유·다시 시도 | 0%로 표시하지 않음 |
| 리셋 시각 경과 | ‘예정 시각 지남 · 확인 필요’ | 회복 완료 알림과 구분 |
| 기록 부족 | ‘기록 모으는 중’, 실제 수집 범위 | 예측·가치 판단 숨김 |

Mac·iPhone·위젯·알림이 같은 상태 정의를 사용한다. 색 외에 문구·기호로도 상태를 구별한다.

## 6. 구현 순서와 완료 조건

### 1차 — 매일 쓰는 핵심 경험

1. 공통 상태·표시 범위·추천 그룹 규칙 정의. 예약 리셋과 확인된 회복을 분리.
2. 단일 계정 핵심 카드, 기준 계정 유지, 설명 가능한 대안, 목적지가 정확한 실행 버튼.
3. Mac 전체 계정 화면과 상세. 메뉴 목록 간소화.
4. iPhone 타일·위젯에 같은 상태 정의 적용, 중복 카드 제거.
5. 첫 조회 성공을 기준으로 온보딩 수정, 알림 수신 확인.

완료 조건:
- 1계정 연결 후 잔여량·리셋·열기까지 추가 계정 없이 사용 가능.
- Claude 5계정의 세션·주간을 같은 형식으로 비교 가능.
- 그룹이 다른 계정은 기본 추천 후보에 포함되지 않음.
- 모든 계정 오류/소진/오래됨이어도 빈 카드나 100% 정상 표시가 나오지 않음.
- iPhone에서 리셋 시각이 지나도 확인 전 회복을 확정하지 않음.
- 실행 버튼과 실제 열린 앱·계정 범위가 일치함.

### 2차 — 결제 전 점검

1. ‘이번 달’을 비용·결제·관측 기록 중심으로 개편하고 가치 판단 문구 제거.
2. 계정별 일간 관측 요약 추가: 마지막 증가 관측, 실제 관측일/시간대, 공백, 출처. 현재 장기 장부의 주기 최고값만으로 사용일을 복원하지 않음.
3. 데이터 확보 후 사용 적음 안내 기준 검증. 기준 충족 전에는 사실만 표시.
4. iPhone 월간 탭·동기화는 Mac 데이터가 안정된 뒤 추가.

완료 조건: 금액 누락·다중 통화·연간 구독·회사 부담·수집 공백에서도 실제 결제액/미사용을 잘못 단정하지 않음.

### 이번 범위에서 하지 않는 것

통합 AI 채팅, 서비스 간 자동 라우팅, 무인 계정 전환, 대화 자동 이전, AI 뉴스, 모델 순위, 사용량 경쟁, 팀 관리자, 서비스 대량 추가, 사용률 기반 낭비 금액 계산.

## 7. 검증 계획

- 초기 사용자 약 10명, 2주. 단일 계정 사용자와 3~5계정 사용자를 함께 포함한다.
- 첫 조회 성공까지 걸린 시간과 연결 실패 지점을 기록한다.
- ‘지금 어디서 쓸 수 있나’와 ‘언제 다시 쓸 수 있나’를 화면만 보고 올바르게 답하는지 관찰한다.
- 추천 이유를 이해하는지, 추천 후 열기 행동이 실제 도움이 됐는지 확인한다.
- 7일/14일 뒤 계속 켜 두는지와 떠난 이유를 묻는다. 앱 실행 횟수를 핵심 성공 지표로 삼지 않는다.
- 오래된 값을 정상으로 오해한 사례, 잘못된 계정 실행, 중복 알림을 우선 기록한다.
- 추천 버튼 클릭은 ‘중단 방지 성공’으로 집계하지 않는다. 사용자의 실제 경험을 별도로 묻는다.
- 초기 검증은 동의한 인터뷰·테스트 기록으로 진행한다. 서버 분석 수집을 이번 기획만으로 자동 추가하지 않는다.

## 8. 현재 구현 확인 근거

- `Tokta/Core/NowPick.swift`: 계정 수 1이면 카드 없음, 계정 고정/서비스 고정·대안 로직.
- `Tokta/Core/Recommendation.swift`: 같은 서비스 후보의 병목 잔여율, 오래된 값·오류 제외.
- `Tokta/UI/MenuContentView.swift`: 핵심 카드와 전체 목록, 구독료 하단, 월간 창 이동.
- `Tokta/UI/MainWindow.swift`: 연결/알림 2단계, 구독 가치·유휴·절약 문구, 타임라인.
- `Tokta/Core/Insights.swift`, `Ledger.swift`: 주기별 최고 사용률 기반 월간 해석. 계정별 촘촘한 관측 범위와 실제 사용일을 대신할 수 없음.
- `Tokta/UI/AccountOpen.swift`: 실제 실행 목적지와 계정 제어 가능 범위.
- `Shared/WidgetData.swift`, `Refills.swift`: 리셋 시각 기반 추정·회복 계산.
- `Tokta/Core/Alerts.swift`: 임박/예측 중복 억제, 예약 회복 문구, iPhone 기본 수신처.
- iPhone 실제 설치·타일·알림 후속은 [[2026-10-15 iPhone 앱]] 참조. 코드 존재와 실기기 검증 완료를 구분한다.
